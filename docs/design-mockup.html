Navigation Structure

Tab: Scorecard
  ├── No round → Course Selection (Home)
  │      ├── push → New Course (form, pops back on save)
  │      └── Next → push → Player Config
  │                        ├── + Add Player → Bottom Sheet (search/create)
  │                        └── Start Round → replaces stack with ↓
  └── Active round → Scoring (accordion per player)

Tab: Rounds (unchanged for now)
  └── Round history / current round summary

Adaptive Scoring Layout (1-4 Players)

The scoring UI adapts based on player count. Fewer players = larger chips, no accordion needed. More players = compact accordion with auto-expand. The threshold for accordion behavior is 3+ players. Hole info and progress bar are always centered.

Players Layout Chip Size Behavior
1 No accordion - single expanded card Large (64px) Always expanded. Spacious layout.
2 No accordion - both cards expanded Medium (44px) Both visible and scoreable without collapsing.
3 Accordion - one expanded at a time Standard (46px) Auto-advances to next unscored. Tap to expand any.
4 Accordion - one expanded at a time Standard (46px) Same as 3. All fit on screen without scrolling.

Color Themes (User-Selectable)

The app supports multiple color themes, togglable from a settings/preferences area. All themes use the same semantic token structure so switching is instant. Themes are implemented via a ThemeProvider context wrapping the app.

Implementation Notes:
  • Each theme defines: background, primary, primaryDark, accent, textTitle, textBody, textMuted, cardBg, chipBg, chipText
  • Components consume colors via useTheme() hook - no hardcoded hex values
  • Styles are generated with useMemo keyed on the current theme
  • Theme preference persisted with AsyncStorage
  • Switching is instant (no reload needed)
