Tee Time – UI Design Reference

The full app: three persistent tabs (Home, Score, You) with a fixed header banner and bottom tab bar. The Score tab owns the round flow — course selection → player setup → scoring — and locks the round once it begins.

Design principles.
• Compartmentalized navigation. Header banner and tab bar are always visible. No flow takes over the entire screen.
• Locked round (Model B). Once Start Round is tapped, the course and player roster are frozen for that round's lifetime. Scoring becomes the Score tab's effective root and has no back navigation. Round-level actions (Finish / Abandon / Scorecard) live in the header's ⋯ overflow menu.
• Tab-switch state preservation. Switching to Home or You mid-round preserves all state — including in-progress score entries. Returning to Score lands the user on the exact screen they left.
• Future flexibility is additive. The locked model is a deliberate v1 choice. Mutations (e.g., add player mid-round, change course) can be layered on later as discrete features without restructuring the data model.
• Player count constraints (v1). Min 1 (You is always included and non-removable), max 4. Once 4 players are present, the + Add Player button and Quick-add + icons are disabled; the Add Player sheet hides its add affordances. Duplicate adds are prevented.
• Modal sheets are exceptions to persistent chrome. The Add Player sheet and the round-actions sheet are modal: while open, the tab bar is visually present but non-interactive (taps on it are absorbed by the scrim). Dismissing the sheet restores tab interactivity. This keeps modal commits atomic.

Tabs at a glance

Three tabs. Home is the default landing tab. The header's left slot shows the active tab name on a tab's root screen, or a back button on sub-screens (see Score flow below). Adaptive scoring layout (1–4 players)

The Scoring screen adapts to the number of players. Fewer players = larger chips, no accordion. Three or more players = compact accordion with one expanded at a time and auto-advance. The persistent header and tab bar are always present — these mocks show the body content only.

Empty space ideas (1–2 players)

With 1–2 players the scoring screen has unused vertical space below the player cards. These are conceptual ideas for what could fill that space meaningfully. None are implemented yet — pick one (or none) for v1 and revisit later.

💡 Idea 1: Inline mini-scorecard

Condensed scorecard grid below the accordion — hole numbers across the top, scores filled in as the round progresses. At-a-glance context without leaving the scoring screen.

💡 Idea 2: Round stats / running summary

Live stats: total vs. par, fairways hit, putts (if tracked later), best/worst hole so far. A small dashboard that grows richer over the round.

💡 Idea 3: Larger hole illustration

Expand the hole header — bigger badge, more hole info (yardage, handicap index), maybe a simple par indicator. Lets the scoring area breathe.

💡 Idea 4: Adaptive chip size

Already covered in the adaptive scoring layouts above: when fewer players are present, chips grow and the card has more padding for a more relaxed feel.

Color themes (user-selectable)

The app supports multiple color themes, switchable from the You tab (or settings). All themes use the same semantic token structure so switching is instant. Implement via a ThemeProvider context wrapping the app; components consume colors through a useTheme() hook with no hardcoded hex values. Persist the preference (e.g., AsyncStorage).

Navigation map

Tab-level structure. Each tab maintains its own navigation stack. Switching tabs preserves the stack and all in-flight state, including an active round. The Score tab has two distinct root states depending on whether a round is active.

Tab: Home
  └── Home (TODO — content TBD)

Tab: Score
  ├── No active round → Course Selection (root)
  │     ├── + Create New Course → push New Course form (pops on save with new course pre-selected)
  │     └── Next → push Player Config
  │         ├── + Add Player → present Add Player bottom sheet
  │         └── ⛳ Start Round → commits round; replaces stack with ↓
  └── Active round → Scoring (root, locked — no header back)
       ├── ⋯ → present Round actions sheet (Scorecard / Finish / Abandon)
       ├── ← Back / Next → → navigate within already-played holes
       └── 🏁 Finish Round (Hole 18 only) → end round; return to Course Selection

Tab: You
  └── You (TODO — content TBD)

Tab switches preserve all stack state and in-flight scoring data.
